# Contributing

This repository distributes shared Sniftr guidance and owns provider-specific
packaging. Read [AI interface guidelines](https://github.com/talshapiro/sniftr/blob/main/docs/development/ai-interface-guidelines.md)
before changing skills, references, or their distribution.

## Layout

- Author canonical skills and references in the `sniftr` repository. Root
  `skills/` here contains synced distribution copies; do not edit them directly.
- Authoring guidelines remain in `sniftr`; do not copy them into this repository.
- Prepare Codex, Claude Code, and Cursor skill copies through `prepare:skills`.
- Keep provider-specific installation details inside `providers/`.
- Maintain Kiro's `plugin.json`, `mcp.json`, and `dev.kiro/` at the repository
  root so users can import the whole repository. Kiro uses root `skills/`
  directly; no Kiro copies are generated by `prepare:skills`.
- Author shared workflow/runtime examples alongside the canonical skill in
  `sniftr`. Keep provider-specific packaging examples here.

## Preparing Provider Packages

Before installing or validating a modified plugin locally, prepare its provider
packages from the shared files in this checkout:

```sh
npm run prepare:skills
```

This prepares the Codex, Claude Code, and Cursor packages. Kiro uses the root
package directly.

## Codex Validation

Check the Codex package before publishing or opening a release PR:

```sh
npm run validate:codex
```

This checks release-version consistency and the presence of the marketplace,
plugin manifest, MCP configuration, and skills directory. It requires Node.js
and npm, with no separate validator setup. These basic checks do not validate
the full Codex schema or replace testing installation and use in Codex.

The plugin manifest should not contain placeholder values. Run `npm run validate:claude`, `npm run validate:cursor`, and
`npm run validate:kiro` to check the other provider packages.

Run `npm run test:versions` when changing the version-preparation script.
